# Лабораторная работа № 8 — ExecutorService и конкурентная обработка

**Профиль:** программная инженерия.

## Подготовительная часть
Три `Callable<Integer>` возвращают 10, 20 и 30. Executor из двух потоков запускает их, а `Future` собираются в порядке отправки. Тест проверяет `[10, 20, 30]` и завершение executor владельцем в `finally`.

## Обязательная часть
Реализованы оба метода `BatchProcessor<T,R>` с сохранением публичных контрактов преподавателя. Последовательный метод обрабатывает элементы циклом. Конкурентный метод отправляет `Callable` в переданный executor и читает `Future` в порядке входа. Задачи не записывают данные в общую коллекцию.

`TaskFileCounter` читает независимые текстовые файлы в формате ЛР 5 и возвращает количество корректных записей. Неверные строки не учитываются; отсутствующий файл и неправильный заголовок дают ошибку соответствующего элемента. Локальная копия loader позволяет не зависеть от `lab05`.

`BatchProcessor` не закрывает чужой executor. Вызвавший код делает это в `finally`. Ошибка отдельного элемента сохраняется в `TaskResult`, остальные результаты остаются. Прерывание конкурентного метода передаётся вызывающему коду, а незавершённые futures отменяются. Последовательный метод не имеет `throws InterruptedException`, поэтому восстанавливает флаг прерывания и завершает обработку через `IllegalStateException` с причиной. Дополнительно реализована отмена futures при прерывании.

## Тестирование
Проверяются пустой набор, успешные задачи, частичная ошибка, сохранение входа, порядок при управляемой задержке через CountDownLatch, обработка реальных временных файлов, повторное использование переданного executor, его завершение владельцем, прерывание рабочего и вызывающего потока. Thread.sleep и проверки ускорения не используются.
